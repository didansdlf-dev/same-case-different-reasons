# Same Case, Different Reasons

**Measuring the Fidelity of LLM-Generated Explanations to Their XAI Evidence**

Reproducibility code for the study: data preparation, model training,
attribution, extractor validation, a pre-experiment power check, and the two LLM
experiments (generation/delta and quality/fidelity), together with the prompts
and the result tables and figures.

## What the study does

An explainable-AI (XAI) method such as SHAP or LIME produces a vector of signed
feature attributions. A large language model (LLM) is increasingly used to
rewrite that vector as a short natural-language explanation a non-expert can
read. This study asks whether the generated text **faithfully reports the
attributions it was given**, whether two explanations of the same case **cite
the same reasons**, and — when they differ — **at which pipeline stage** the
difference is introduced:

- the **evidence stage** — the prediction model and the attribution method decide
  which drivers exist;
- the **generation stage** — the LLM and the prompt turn those drivers into prose.

Each explanation is decomposed into a set of *(feature, direction, rank)* claims
by an LLM extractor validated against human coding. Content variation is
attributed to a stage and estimated at the case level with cluster-bootstrap
intervals. Two LLM-as-a-judge graders then score each explanation in isolation,
to test whether conventional quality scoring detects content divergence.

**Headline findings.** Across six datasets, content variation originates
overwhelmingly in the evidence stage; changing the generator or the prompt leaves
content at or below the baseline of regenerating the same explanation twice. A
constrained prompt removes the residual omission gap and the differences between
generators. A deliberately contradictory verdict does **not** induce direction
rewriting in the models studied (reported as a null). Isolated quality scoring is
only weakly related to content divergence.

## Domains

The pipeline is domain-general and is run over six public tabular
binary-classification datasets:

| Domain key | Dataset | Target (positive class) | Role |
|---|---|---|---|
| `credit_personal` | Personal-loan credit risk | loan default | primary (high-stakes) |
| `credit_corporate` | Corporate credit rating | investment grade | added |
| `credit_taiwan` | Taiwan credit-card clients | default | added |
| `credit_gmsc` | "Give Me Some Credit" | serious delinquency | added |
| `income_adult` | Adult census income | income above 50K | added |
| `churn` | Telco customer churn | churn | control |

Engineered or duplicated add-on columns are dropped; each dataset's native raw
features — including demographic columns, per benchmark convention — are kept.
Categoricals are one-hot encoded with the first level held out as reference.

**Adverse-decision subgroup.** Every content result is reported for the full
sample **and** for the adverse-decision subgroup — the subjects who would receive
the unfavourable decision (declined applicants, speculative-grade issuers), who
have the strongest claim to an explanation. The subgroup is defined only for the
credit datasets; `income_adult` and `churn` have no adverse-action analog.

## Pipeline

Notebooks run in numeric order; each reads the artefacts the previous ones wrote.
Notebooks 01–05 use no LLM API. **Notebooks 06 and 07 are the LLM experiments**
and require an API key; they are isolated at the end so they can be run
separately on a machine with the key.

| # | Notebook | API | Purpose |
|---|----------|-----|---------|
| 01 | `data_preparation` | – | Load and clean the six datasets; fixed stratified 70/30 split; one-hot encode; write the feature registry |
| 02 | `model_training` | – | Train XGBoost, LightGBM, random forest per domain under an AUC-parity constraint |
| 03 | `attribution_evidence` | – | Sample cases by predicted risk (adverse stratum included); compute SHAP and LIME (settings stated); write the evidence blocks |
| 04 | `extractor_validation` | – | Extractor self-stability, fidelity to the supplied evidence, and the human-coding decision gates |
| 05 | `power_and_design` | – | Pre-experiment power and precision simulation; design recommendation |
| 06 | `generation_and_delta` | ✅ | Generate the corpus, extract claims, measure content distance, run the main delta analysis, and the mixed-effects + coverage appendix tables |
| 07 | `quality_and_fidelity` | ✅ | Fidelity by condition, the LLM-as-a-judge blind-spot analysis, and the controlled contradictory-verdict test |

Each notebook is a single self-contained cell. Every LLM call in 06–07 is cached
on disk by a key over all inputs, so an interrupted run resumes without
re-issuing completed calls and a repeat run regenerates nothing.

## Reproducing the study

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # then fill in OPENAI_API_KEY
```

`.env` (kept at the project root, one level above `notebooks/`):

```
OPENAI_API_KEY=sk-...
LLM_MODEL_WEAK=gpt-4o-mini
LLM_MODEL_MID=gpt-5.4-mini
LLM_MODEL_STRONG=gpt-5.4
```

Then run the notebooks in order (01 → 07). The models are read by tier: the mid
tier is the reference generator, the strong tier the deterministic extractor, and
the mid/weak tiers the two judges.

Two scale knobs keep 01–05 tractable on a modest machine and should be raised for
a paper-scale run: `N_CASES_MAIN` and `LIME_N_SAMPLES` in notebook 03, and
`TRAIN_FIT_CAP` in notebook 02 (set to `None` to fit on the full training split).

## Figures and manuscript tables

`results/figures/` holds every figure (PNG + PDF, 600 dpi, grayscale; no baked-in
captions). The two schematic method figures (`fig01_pipeline`,
`fig03_delta_design`) are not analysis output; their design briefs are in
`figures/specs/*.json` (16:9, opaque grayscale). Notebook 06 also writes
`\input`-ready LaTeX for the appendix tables in `results/tables/`
(`tab_mixed_var.tex`, `tab_mixed_fe.tex`, `tab_mixed_agree.tex`,
`tab_coverage.tex`): the mixed-effects variance decomposition, fixed effects,
pairwise-vs-mixed agreement, and distance coverage.

## Conventions

- All random operations use a fixed seed (42).
- Figures are grayscale, saved as PNG and PDF at 600 dpi; series are distinguished
  by line style and shading rather than colour.
- No notebook prints a file path (author anonymity).
